# Markdown 教程文档美化规范

## 概述

本文档定义了 OpenCode 教程文档的美化标准和最佳实践，确保教程风格统一、阅读体验友好。

---

## 1. 标题层级

### 规则

- 主标题使用 `##` 开头（如 `## 安装 OpenCode`）
- 二级标题使用 `###` 开头
- 避免使用 `#` 作为内容标题（保留给文件标题）
- 中文标题后面不跟英文

### 示例

```markdown
## 第一章：打开 OpenCode

### 1.1 安装 OpenCode

### 1.2 启动与配置
```

---

## 2. 目录结构

### 规则

- 长教程（>3 个主要章节）建议在文件顶部添加目录
- 目录使用 Markdown 链接格式
- 目录标题使用 `## 目录` 或 `## 📋 目录`

### 示例

```markdown
## 目录

- [什么是 OpenCode](#什么是opencode)
- [安装 OpenCode](#安装opencode)
- [使用方式](#使用方式)
- [常见问题](#常见问题)
```

---

## 3. Emoji 使用

### 规则

- 章节标题可添加 emoji 前缀（💡、🚀、⚡、📌、⚠️、✅）
- 不要过度使用，每个主要章节 1-2 个为宜
- 常用 emoji 对照：

| 场景 | Emoji |
|------|-------|
| 提示/注意 | 💡 |
| 警告 | ⚠️ |
| 步骤开始 | 🚀 |
| 完成/检查 | ✅ |
| 重要强调 | 📌 |
| 代码/命令 | ⚡ |
| 问题解决 | 🔧 |

---

## 4. 代码块规范

### 规则

- 所有代码块必须标注语言类型
- 终端命令使用 `bash` 或 `powershell`
- 文件路径使用 `text` 或 `bash`
- 命令前的提示符（`$`、`>`、`#`）保留

### 示例

```bash
# 安装 OpenCode
npm install -g opencode-ai

# 验证安装
opencode -v
```

```powershell
# Windows PowerShell
npm install -g opencode-ai
```

---

## 5. 表格格式

### 规则

- 使用标准 Markdown 表格格式（`|` 分隔）
- 表头使用 `---` 分隔
- 中英文混排时英文加粗或引号

### 示例

| 命令 | 作用 | 示例 |
|------|------|------|
| `/help` | 查看帮助 | `/help` |
| `/new` | 新建会话 | `/new` |
| `/models` | 选择模型 | `/models` |

---

## 6. 引用块

### 规则

- 重要提示使用 `>` 引用块
- 多行引用使用多个 `>`
- 可结合 emoji 使用

### 示例

> 💡 **提示**：这是 OpenCode 最强大的功能。

> ⚠️ **注意**：国内用户需要配置网络代理。

---

## 7. 分隔线

### 规则

- 章节之间使用 `---` 分隔
- 避免过多分隔线（每个主要章节后 1 个）

---

## 8. 有序列表

### 规则

- 步骤类内容使用有序列表
- 每一步保持独立性
- 可在步骤前添加emoji

### 示例

1. 🚀 安装 Node.js
2. ⚡ 安装 OpenCode
3. ✅ 验证安装

---

## 9. 无序列表

### 规则

- 并列内容使用 `-` 或 `*`
- 保持同级缩进一致
- 列表项内容不宜过长

### 示例

- 第一项内容
- 第二项内容
- 第三项内容

>

## 11. 命名规范

### 文件命名

- 教程文件放在 `docs/` 目录下，使用英文小写加连字符命名
- 有序号的章节使用数字前缀（如 `01-intro.md`）
- 文件名中不要使用 `#`、空格和中文，避免链接和站点生成出问题

### 示例

```
docs/01-meet-opencode.md
docs/02-use-ai-agent.md
docs/03-create-writing-agents.md
docs/bonus-git-push-to-github.md
```

## 12. 语言规范

### 规则

- 正文使用简体中文
- 英文术语首次出现时添加中文解释
- 代码和命令保持英文原样

### 示例

- OpenCode（开源 AI 编程助手）
- Terminal（终端）

## 13. 插入图片

遇到【插入图片+图片格式文件名】的范式，插入目录 `Assets/Pictures/` 之下的正确名称的图片。

教程文件位于 `docs/` 目录，所以图片路径使用相对路径 `../Assets/Pictures/文件名.png`，不要用以 `/` 开头的绝对路径（在 GitHub 上无法显示）。

## 13.5 证据标签（V2 教程专用）

教程里的关键结论（命令、快捷键、配置字段、默认行为、版本差异）需要标明来源，方便读者判断可信度，也方便以后版本升级时重新核对。

| 标签 | 含义 | 示例 |
|------|------|------|
| `官方文档` | 来自 `opencode.ai/v2/docs` | "V2 只识别 `AGENTS.md`" |
| `实测` | 在本机 OpenCode V2 上实际运行验证 | "edit 只做精确匹配（实测）" |
| `第三方` | 来自 GitHub issue、第三方文章，未自行验证 | 不写进正文结论，仅在需要时说明 |
| `待验证` | 暂无可靠证据 | 不写进教程，记录到 `VERSION.md` 的待验证清单 |

### 写法

- 用括号在句末标注，例如"（实测）"；或使用引用块开头标注，例如"> ✅ **实测**：……"
- 每章开头的"版本说明"写明适配的 OpenCode 版本
- 没有证据的内容宁可不写，不要写成定论

## 14. 目录跳转规范（重要！防止跳转失效bug）

### 问题背景

当标题包含 **emoji** 时，不同的 Markdown 渲染器（GitHub、GitLab、VS Code）对锚点的生成规则不一致，导致目录点击无法跳转。

### 错误示例 ❌

```markdown
## 目录

- [什么是 OpenCode](#什么是opencode)  <!-- 链接失效 -->
- [安装 OpenCode](#安装opencode)      <!-- 链接失效 -->

---

## 💡 什么是 OpenCode

## 🚀 安装 OpenCode
```

### 解决方案 ✅

**使用 HTML 自定义锚点**，确保跨平台兼容：

#### 步骤 1：为标题添加 HTML 锚点

```markdown
## 💡 什么是 OpenCode <a id="what-is-opencode"></a>
## 🚀 安装 OpenCode <a id="install-opencode"></a>
```
特别注意：添加HTML锚点的语法是<a id="xxxxxx"></a>

#### 步骤 2：目录链接指向自定义锚点

```markdown
## 目录

- [什么是 OpenCode](#what-is-opencode)  <!-- 正确 -->
- [安装 OpenCode](#install-opencode)    <!-- 正确 -->
```

### 锚点命名规范

| 规则 | 示例 | 说明 |
|------|------|------|
| 英文小写 | `what-is-opencode` | 统一使用小写 |
| 连字符连接 | `install-opencode` | 用 `-` 代替空格 |
| 简洁描述 | `core-tools` | 不要太长 |
| 避免特殊字符 | - | 只用字母、数字、连字符 |

### 完整示例

```markdown
## 📋 目录

- [什么是 OpenCode](#what-is-opencode)
- [安装指南](#install-guide)
- [核心功能](#core-features)

---

## 💡 什么是 OpenCode <a id="what-is-opencode"></a>

内容...

---

## 🚀 安装指南 <a id="install-guide"></a>

内容...

---

## ⚡ 核心功能 <a name="core-features"></a>

内容...
```

### 注意事项

1. **锚点位置**：必须紧跟在标题行末尾，不能换行
2. **唯一性**：确保每个锚点名在文档中唯一
3. **兼容性**：HTML `<a id="">` 所有平台都支持
4. **备选方案**：如果标题无 emoji，可直接使用 Markdown 标准锚点
